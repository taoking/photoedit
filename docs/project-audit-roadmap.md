# PhotoEdit 项目审计与后续迭代路线图

审计日期：2026-08-10
审计基线：`main` / `61ad1c0`
验证环境：iPhone 17 Pro Simulator（iOS 26.5）；既有 iPhone 16 Pro 真机导入验证记录

## 1. 结论

PhotoEdit 已具备可信的图像处理底座和较宽的专业功能面：非破坏状态、Preview/Export 分流、RAW、HDR、LUT、批量、局部调整和视频均有实现，自动化测试对核心图像正确性覆盖较好。

当前主要短板已经从“能否正确处理图片”转为“用户能否轻松、安心、连续地完成编辑”。编辑器在标准竖屏下可用，但固定高度参数面板会隐藏内容；横屏和大字体下照片工作区显著萎缩。裁切和局部蒙版缺少直接在照片上操控的控件，会话不持久化，导出缺少持续可见的进度/取消入口。部分底层错误还会被 `try?` 静默吞掉。

产品阶段判断：**功能完整的内部 Beta，尚未达到稳定日用版的体验完成度**。下一阶段应定义为“产品可用性与会话可靠性”，不建议优先继续增加滤镜数量。

## 2. 审计依据

- 完整执行 `xcodegen generate`。
- 完整执行 iPhone 17 Pro / iOS 26.5 Simulator 单元测试：76 项通过，0 失败。
- 模拟器实际导入 `DSC03305.jpg`，检查首屏、照片适配、顶部工具栏、底部工具栏、光线、HSL、曲线、LUT、裁切、局部蒙版和导出结果页。
- 检查竖屏、横屏以及 `accessibility-extra-extra-large` 动态字体。
- 静态检查 7,846 行 Swift/配置代码、项目结构、全部测试目标和真实媒体验收文档。

本次没有重新完成 Sony ARW/DNG、真实 HDR/gain-map、长视频、4K 音画同步和 12/24/48MP 性能实测；相关内容仍是风险项，不能写成已验证结论。

## 4. 已做得好的部分

1. 照片预览已经真正优先于控件，主工作区背景、顶部工具栏和底部工具栏形成了稳定层级。
2. `EditState` 是可编码纯值模型，图像管线、导出器与 UI 基本解耦，便于继续演进会话和历史功能。
3. 单一长期 `CIContext`、Preview 下采样、generation guard 和取消逻辑避免了大量常见图像编辑器错误。
4. RAW 默认值、HDR 高光保护、LUT encoding 校验、metadata 方向/尺寸清理体现出正确性优先的产品原则。
5. 导出完成页的“照片 / 分享 / 文件”分流清楚，采用系统组件，学习成本低。
6. AppIcon 质量合格，深色光圈与青/紫/橙边缘和应用视觉体系相符。

## 5. P0：下一阶段首先解决

### P0-1 参数面板和自适应布局

现状：参数面板依赖 184–240pt 固定高度。光线面板的第四个滑杆、HSL 的后续滑杆、曲线底部说明、LUT 卡片说明和局部蒙版内容都需要在没有滚动提示的狭小区域里查找。横屏时照片缩成很小的条带；大字体下控件占据大部分画面。

影响：用户无法快速确认“这个工具还有什么”，也无法在调整时持续观察照片。横屏与辅助功能字号接近不可用。

建议：

- 参数区改为可交互 detent（收起 / 紧凑 / 展开），内容提供明确滚动反馈和正确 bottom inset。
- 横屏改为照片在左、参数在右的双栏，而不是继续纵向堆叠。
- 根据 Dynamic Type 切换工具栏样式；辅助字号使用图标主导或可滚动列表，不把固定 58×54 单元强行放大。
- 移除面向实现的说明文字，把必要解释放到帮助或信息按钮。

验收：竖屏、两种横屏、标准字号和 Accessibility XXL 下无重叠/截断；任一参数都可发现；展开参数时照片仍保持可判断的可视面积。

### P0-2 当前编辑会话不持久化

现状：关闭当前照片或应用进程结束后，当前 `EditState`、源照片引用和 undo 历史均消失。关闭按钮没有“保留编辑 / 放弃”语义，也没有最近项目入口。

影响：长时间 RAW、曲线、局部蒙版编辑存在误触或进程中断后全部丢失的风险，是日用版的可靠性缺口。

建议：增加 `EditorSessionStore`，保存源资源标识/安全书签、EditState、预览缩略图、编辑时间和 schema version；首页增加“继续编辑/最近项目”；有未保存变化时关闭提供清晰选择。

验收：强制终止并重新打开应用后可恢复同一照片和全部参数；资源失效时给出重新定位流程；旧 schema 可迁移或明确失败。

### P0-3 导出缺少持续反馈和取消

现状：点击“生成”后导出设置页立即关闭；主编辑器没有明显导出进度、状态或取消入口。设置页内部的 ProgressView 实际上几乎不可见。再次导出会取消上一任务但没有向用户解释。

影响：24/48MP、RAW、HDR 导出时用户会误以为操作无效并重复点击。

建议：主界面展示持久导出状态条/任务面板，禁用重复提交，提供取消和阶段文字；导出完成后保留明确成功反馈。

验收：提交后 200ms 内出现反馈；任务可取消；同一时刻只有一个单图导出；取消、失败和成功均有不同结果状态。

### P0-4 消除静默失败

现状：视频逐帧处理在 `VideoEditing.swift` 中用 `try?` 吞掉滤镜错误并退回原始帧；预设/LUT 的收藏、重命名、删除和导出也有多处 `try?` 直接忽略失败。

影响：视频可能在用户不知情时导出未套用效果的帧；资料库操作失败时 UI 看似成功，破坏可信度。

建议：视频合成建立可传播/锁存的渲染错误状态，禁止静默回退；Repository 操作统一通过 ViewModel 呈现错误并保证文件与 metadata 事务一致。

验收：注入滤镜、磁盘写入和 metadata 损坏错误时，用户看到明确失败，最终文件不会伪装为成功结果。

## 6. P1：形成真正顺手的编辑器

### P1-1 裁切改为照片上直接操作

当前裁切主要依赖“缩放、水平位置、垂直位置”滑杆。建议增加照片上的裁切框、角/边手柄、三分网格、拖移、双指缩放、拉直角度和比例锁定；旋转/翻转保留为次级动作。

### P1-2 局部蒙版改为照片上直接操作

线性/径向蒙版目前通过 X/Y/半径滑杆编辑，画笔在独立黑色 120pt 画布中绘制，用户无法在照片语境中准确落点。建议在预览层显示蒙版 overlay 和控制柄；画笔直接在照片上绘制，支持显示/隐藏蒙版、擦除、反转、羽化、流量和撤销笔触。

### P1-3 完善调整手感

- 每个滑杆支持双击归零、单项重置、长按/点按数值精确输入。
- 增加细微触觉反馈和零点吸附。
- 增加 redo 和可见历史列表，而不只提供单个 undo。
- “查看原图”改成真正 Button，并支持可发现的按住、锁定比较或左右滑动比较；当前 AX 中它仍表现为 Image。

### P1-4 重整信息架构

“更多”菜单目前同时容纳重新导入、预设、批量、参考图、视频、复制粘贴、重置和关闭，菜单过长且混合不同任务。建议分成：

- 文件/项目：重新导入、关闭、参考图；
- 工作流：预设、复制粘贴、批量；
- 其他媒体：视频；
- 危险操作：重置。

预设与 LUT 应成为真正的浏览面板，提供搜索、收藏、最近使用和更大的可比较缩略图。

### P1-5 可访问性和语言一致性

- 修复大字体与横屏布局；补 VoiceOver 可执行动作、焦点顺序和自定义 rotor/adjustable action。
- 统一中文产品语言：`Color Mixer`、`RAW Decode`、`Creative LUT`、`Technical LUT` 和英文 Photos 权限文案需要统一策略。
- 工具栏 `caption2` 文字太小且对比度低；未选工具不应只靠低透明度区分。
- 为 Reduce Motion、Increase Contrast、Differentiate Without Color 做专项检查。

### P1-6 建立 UI 与性能验收

当前 76 项测试全部是单元/管线测试，没有 XCUITest、截图回归和性能基准。建议增加：

- 导入 → 基础调整 → 撤销 → 导出 → 保存的核心 UI 测试；
- 竖屏/横屏/Dynamic Type/VoiceOver 标识截图测试；
- 12/24/48MP、JPEG/HEIF/RAW/HDR 的首帧、滑杆 P95、峰值内存和导出耗时；
- 65³ LUT 导入与大量 LUT 缩略图性能测试。

特别关注：`ImageAsset` 同时保留原始 Data 与 CIImage，`ExportedImage` 同时保留 Data 与临时文件；65³ LUT 在 `@MainActor` Repository 中同步读取和解析；单一 `ImagePipeline` actor 会让全分辨率导出和预览竞争同一串行执行器。这些是待量化风险，不应在没有基准前声称已经优化。

## 7. P2：功能深度迭代

按投入产出比建议顺序：

1. 基础摄影控制：白色色阶、黑色色阶、清晰度/纹理、去雾、明度/色彩降噪。
2. 项目与图库：最近编辑、版本/快照、编辑复制、批量从 Photos 选择。
3. LUT 产品价值：一组经过验证的内置风格、标签/搜索/排序、前后对比和批量预览。
4. 局部调整：色温、高光/阴影等更多参数；主体/天空自动蒙版必须有明确降级和边缘质量验收。
5. 色彩能力：真正的跨 encoding Technical transform、HDR 安全的 HSL/曲线/LUT；这需要真实参考素材和像素级验证，不能只打开 UI 开关。
6. 视频：时间轴、裁切/修剪、播放期间低延迟预览、导出进度、4K/长视频稳定性；HDR 视频最后处理。
7. 输出：PNG/TIFF（如确有工作流需求）、自定义尺寸、批量冲突策略、metadata 总开关和隐私默认策略。

## 9. Phase 9 完成标准

- iPhone 16 Pro/17 Pro 竖屏与横屏、标准字体和 Accessibility XXL 均无控件重叠或不可达内容。
- 关闭、崩溃或系统回收后可以恢复当前会话；所有破坏性退出都有清楚语义。
- 裁切和三类蒙版都能直接在照片上操作，Preview 与 Export 对齐。
- 导出有可见状态、取消和明确成功/失败，不存在静默回退原始结果。
- 核心用户流程拥有 UI 自动化；单元测试继续全部通过。
- 真实 12/24/48MP、RAW、HDR 和视频基线记录在文档中，未验证项不得标记完成。
